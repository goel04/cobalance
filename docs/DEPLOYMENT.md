# Deploying Cobalance (Supabase + Vercel)

Cobalance is a static Vite/React app hosted on Vercel. All data lives in Supabase:
Postgres (with Row Level Security), Auth, and a private Storage bucket for evidence files.

## 1. Environment variables

The frontend needs exactly two values, both from **Supabase Dashboard → Project Settings → API Keys**:

| Name | Value | Notes |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | `https://<project-ref>.supabase.co` | Public |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_…` | Public by design; RLS protects the data |

**Never** put the secret (`sb_secret_…`) or legacy `service_role` key in a `VITE_` variable, in
`.env.local`, or anywhere in this repo. Every `VITE_` value is compiled into the JavaScript sent to
visitors. The app refuses to start if it is given a secret key.

Local development — create `.env.local` in the repo root (it is git-ignored):

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_<key>
```

## 2. Database

Migrations live in `supabase/migrations` and are applied in filename order:

1. `…0001_schema.sql` — tables, triggers, audit log
2. `…0002_rls.sql` — Row Level Security, role helpers, RPCs, the private `evidence` bucket
3. `…0003_seed_emission_factors.sql` — shared factor library (generated by `scripts/generate-factor-seed.ts`)

Apply with the Supabase CLI (`supabase link --project-ref <ref>` then `supabase db push`) or by pasting
each file into the SQL editor. After applying, paste `supabase/tests/rls_test.sql` into the SQL editor:
it runs in a rolled-back transaction and must end with `ALL RLS TESTS PASSED`.

Locally, `npm run test:db` applies the same migrations to an in-process Postgres (PGlite) and runs the
RLS suite plus the app's own write payloads as several users.

## 3. Supabase Auth settings

**Authentication → URL Configuration**

- Site URL: `https://<your-domain>`
- Redirect URLs (add each):
  - `https://<your-domain>/**`
  - `https://www.<your-domain>/**` (if you serve `www`)
  - `https://<project>-<team>.vercel.app/**` (preview deployments; or the exact preview domain)
  - `http://localhost:5173/**` (local development)

The app sends users back to `/onboarding` after email confirmation and to `/reset-password` from
password-reset emails; both are covered by the wildcards above.

**Authentication → Providers → Email**: keep *Confirm email* on.

**Authentication → SMTP**: configure a custom SMTP sender before launch. Supabase's built-in sender is
heavily rate-limited and meant for testing only.

## 4. Vercel

`vercel.json` sets the build (`npm run build` → `dist`), SPA routing (every path serves `index.html`),
long-term caching for hashed assets, and security headers.

Environment variables: add both `VITE_` values for **Production** and **Preview** (and **Development**
if you use `vercel dev`). Changing them requires a redeploy.

## 5. Moving data from the old browser-only version

Users who used the earlier demo version have data in their browser. After they log in, the app offers
**Settings → Data → Data saved in this browser**: each organisation can be imported into their account
(new ids, files uploaded to private storage, all-or-nothing). The browser copy is only deleted when the
user chooses *Remove browser copy*.
